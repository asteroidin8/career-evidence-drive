# 나의 업무 기록 — v3.0

빠르게 업무 기록을 남기고, 구글 드라이브로 여러 기기의 기록과 피드백을 합치는 개인용 앱입니다.

## 매일 사용하는 방법

1. **기록하기**에서 제목·상황·내가 한 행동·결과를 적고 저장합니다. 태그와 숫자는 선택 항목입니다.
2. **백업**에서 구글 드라이브를 연결하면 자동으로 기록을 가져온 뒤 새 기록을 백업합니다. 연결된 상태에서 저장해도 자동 동기화합니다.
3. **내 기록 → 보기**에서 원본, 피드백, 다듬은 글을 확인합니다. 앱을 열고 연결해 두면 1분마다 새 내용을 확인합니다.
4. 이 사용자의 Codex 작업에는 **매일 오전 6시(한국 시간) 검토**가 별도로 등록되어 있습니다. 웹앱 자체가 AI를 실행하는 것은 아닙니다. 다른 사람이 이 소스를 배포해도 예약은 함께 복제되지 않습니다.

자동 검토는 Codex와 연결된 Google Drive를 사용합니다. 이 컴퓨터와 Codex 앱을 켜 두는 것이 필요하며, 예약 실행·계정 사용량·연결 권한에 따라 지연되거나 사용자 조치가 필요할 수 있습니다. 완성된 피드백은 웹앱의 다음 연결 또는 동기화 때 반영됩니다. 컴퓨터가 꺼져도 휴대폰 웹앱의 로컬 저장과 직접 Drive 백업은 별개로 동작합니다.

## 처음 연결하기

기존과 같은 HTTPS 주소에 배포해야 해당 브라우저의 로컬 기록과 설정이 유지됩니다. 사이트 데이터를 삭제하지 마세요.

Google Cloud에서 Drive API를 활성화하고 **Web application OAuth Client ID**를 만듭니다. 실제 배포 주소의 origin을 Authorized JavaScript origins에 등록하고, Testing 상태라면 본인을 테스트 사용자로 추가합니다. 앱의 **백업 → 처음 연결할 때 설정**에 Client ID를 저장한 뒤 연결합니다. 기존에 저장한 Client ID는 유지됩니다.

권한은 기존 `drive.file`만 사용합니다. 이 앱이 만든 파일 또는 이 앱에 접근이 허용된 파일을 읽고 쓸 수 있습니다. **다른 도구가 만든 파일은 같은 폴더 안에 있어도 이 앱에 보이지 않을 수 있습니다.** 이 경우 Drive에서 백업 JSON을 내려받아 **백업 파일 가져오기**로 넣으세요. 기존 목록과 합치며 일괄 교체하지 않습니다. 기존 v2 Markdown 및 `raw_original` JSON도 지원합니다. 권한을 임의로 전체 Drive 접근으로 넓히지 않습니다.

## 새로고침과 연결 해제

공개 Client ID와 재연결 여부만 LocalStorage에 저장합니다. 비밀번호, Client Secret, refresh token, access token은 저장소에 보관하지 않습니다. 기록 본문 캐시에는 인증 정보가 포함되지 않습니다. 토큰은 메모리에 유지하며 새로고침 시 GIS OAuth token flow로 `prompt:'none'` 재요청을 시도합니다. 브라우저 팝업 정책이나 Google 로그인 상태 때문에 실패할 수 있으며, 그때 **구글 드라이브 다시 연결**을 누르면 됩니다. 처음 업데이트 후 한 번은 직접 연결해야 합니다.

토큰 만료 또는 401 응답 시 재연결 안내를 표시합니다. 연결 해제는 자동 재연결도 끕니다. Google 전체 로그아웃이나 OAuth 권한 철회는 아닙니다.

## 양방향 동기화와 데이터 보존

- **Drive에만 있는 기록 → 앱:** 폴더 안의 접근 가능한 JSON을 모두 조회한 뒤 최신 버전을 가져옵니다. 파일 목록은 다음 페이지까지 확인합니다.
- **앱에서 새로 쓰거나 수정한 기록 → Drive:** 기록별 같은 JSON 파일을 갱신합니다. 새 Markdown은 생성하지 않습니다.
- **양쪽 동시 수정:** 시간을 비교해 임의로 덮어쓰지 않습니다. 백업 탭에서 앱 내용과 Drive 내용을 보여주고 다음 버전으로 사용할 내용을 선택하게 합니다. 선택 전 내용을 별도 로컬 보관하고 Drive의 과거 버전도 유지합니다.
- **기존 백업과 형식 오류:** 가져오기 단계가 실패하면 업로드를 중단합니다. 빈 배열 백업으로 로컬 목록을 비우지 않습니다.
- **삭제:** 삭제는 해당 기기에서만 적용합니다. Drive 파일을 지우지 않으며 다음 동기화에 다시 나타날 수 있습니다. 원격 삭제도 로컬 기록을 지우지 않습니다. 삭제까지 전파하는 미러링은 지원하지 않습니다.
- **오프라인:** 기기에 먼저 저장하고 다음 연결 시 동기화합니다. 저장소 용량 부족은 브라우저 오류로 표시될 수 있으므로 JSON 내보내기도 유지하세요.

## 누적 기록을 위한 저장 구조

기록마다 최신 JSON 파일 하나를 사용합니다. 원본과 피드백·수정본은 같은 JSON의 별도 필드입니다. 수정할 때 파일을 추가하지 않고 같은 Drive 파일 ID를 갱신하므로 댓글과 링크도 유지됩니다. 기존 v2.2의 과거 파일은 자동 삭제하거나 이동하지 않습니다. 기존 기록은 다음 수정 시 최신 파일을 그대로 갱신하며, 과거 파일이 최신으로 다시 나타나지 않도록 이전 관계를 보존합니다.

- 파일 목록의 version을 비교하고 **변경된 파일 본문만 다운로드**합니다. 본문 캐시는 Google 계정과 Client ID별로 분리하여 IndexedDB에 저장합니다. 캐시 사용이 불가능하면 원격 본문을 다시 읽습니다.
- 목록 메타데이터는 전체 페이지를 확인합니다. Drive Changes API 방식은 아니므로 목록 조회 비용은 파일 수에 비례합니다. 본문 전체 재다운로드에 비해 전송량과 요청 수를 줄입니다.
- 미검토 기록의 댓글만 확인하며 기록당 최소 5분 간격, 동기화당 최대 20건입니다. 대기 기록이 많으면 차례로 확인합니다. 내 기록의 AI 새로고침은 선택한 기록을 다시 확인합니다.
- 가져온 기록은 메모리에서 ID로 찾아 합친 뒤 한 번에 로컬 저장합니다. 1,000건을 가져온 다음 변화 없이 다시 동기화하는 테스트에서 추가 본문 다운로드는 0건이었습니다.
- 기존 전체 10MB 제한은 제거했습니다. 개별 파일은 2MB까지 읽습니다. 로컬 원본 저장은 기존 LocalStorage를 사용하므로 브라우저 용량 제한은 여전히 적용됩니다. 수만 건이나 첨부파일을 위한 서버형 데이터베이스는 아닙니다.

저장 형식은 호환성을 위해 format=career-evidence-record-v3을 유지하고 storageVersion=4를 추가합니다. id는 고정 기록 식별자, record는 원본과 AI 필드, parents는 이전 내용의 해시입니다. legacyParents는 이전 앱에서 이미 생성된 파일들의 관계를 고정 보존합니다. 정상적인 이후 수정에서는 관계 배열이 계속 누적되지 않습니다. 해시 계산은 기존 sync.js와 같습니다.

쓰기 직전 Drive v2의 etag와 본문을 다시 확인하고 If-Match 조건을 붙여 갱신합니다. 그 사이 원격이 바뀌어 412가 오면 업로드를 멈추고 로컬 수정을 보존합니다. 다시 동기화하여 충돌 내용을 확인하세요. 조건부 쓰기가 실패할 때 무조건 덮어쓰는 우회는 없습니다. 인증은 기존 GIS token flow와 drive.file 범위를 유지합니다.

이후 수정 이력은 Drive 자체 파일 버전에 맡깁니다. **영구 보관은 보장되지 않습니다.** Google은 고정하지 않은 이전 버전을 일정 기간 또는 버전 수에 따라 정리할 수 있습니다. 중요한 시점에는 앱의 JSON 백업을 별도로 보관하세요. 기존 별도 과거 JSON은 그대로 남습니다.

참고: [Drive 파일 갱신](https://developers.google.com/workspace/drive/api/reference/rest/v2/files/update), [Drive 버전 보관](https://developers.google.com/workspace/drive/api/guides/manage-revisions).

## 자동 검토 댓글 계약

Codex는 최신 JSON 원본을 수정하지 않고 그 파일에 댓글을 남깁니다. 중복·충돌을 확인한 후 `CAREER_EVIDENCE_AI_REVIEW` 한 줄 다음에 JSON을 기록합니다. 필드는 `entryId`, `reviewedOriginal`, `reviewedAt`, `status`, `feedback`, `revision`, `recommendedSkills`, `recommendedValue`, `portfolioNote`입니다.

`entryId`는 파일의 최상위 id입니다. `reviewedOriginal`은 검토한 record의 situation/action/result/followUp을 정확히 복사한 객체입니다. 앱은 원본 일치 여부를 확인해 오래된 피드백이 수정된 원문에 붙지 않게 합니다. `revision` 역시 situation/action/result/followUp 문자열 객체입니다. 원본과 AI 수정본은 별도 필드로 유지됩니다.

## 확인한 범위

모의 Drive로 두 기기의 업로드·복원·수정·충돌·해결·피드백 전파·재시도·중복 방지·오프라인·형식 오류·목록 페이지 처리와 기존 백업 가져오기를 검증했습니다. 브라우저에서 한국어 입력 화면, 로컬 저장 및 새로고침 후 보존을 확인했습니다. 이번 v3의 실제 Google 계정 연결과 조건부 Drive 갱신은 로그인된 테스트 브라우저가 없어 확인하지 못했습니다. 배포 후 연결하여 저장·수정·새로고침을 확인해야 합니다.
